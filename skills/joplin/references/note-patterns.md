# Note Patterns

Use these as adaptive patterns, not mandatory templates. Omit sections that do not add value.

## Technical explanation

- Summary
- Context and Relevance
- Key Concepts
- How It Works
- Example
- Implications
- Open Questions
- References

## Debugging

- Problem
- Context and Impact
- Observed Behavior
- Expected Behavior
- Evidence
- Leading Theory
- Alternative Theories
- Experiments or Checks
- Resolution
- Follow-up Work

Label theories and assumptions explicitly. Preserve exact errors, logs, commands, identifiers, timestamps, and measured values when relevant.

## Decision

- Decision
- Context
- Options Considered
- Rationale
- Tradeoffs
- Consequences
- Risks
- Follow-up Actions

Clearly separate the final decision from proposals that were considered but not selected.

## Investigation

- Question
- Context
- Findings
- Evidence
- Interpretation
- Unknowns and Assumptions
- Recommended Next Steps

Do not present an inference as a confirmed finding.

## Architecture

- Purpose
- Context and Constraints
- Components
- Data Flow or Request Flow
- Interfaces and Events
- Failure Modes
- Tradeoffs
- Open Questions

Use ordered steps for sequences and preserve exact component, endpoint, event, topic, and datastore names.

## Meeting summary

- Purpose
- Context
- Topics Discussed
- Decisions
- Open Questions
- Action Items

Attribute owners and dates only when supported by the source material.

## Implementation plan

- Objective
- Scope
- Proposed Approach
- Work Breakdown
- Dependencies
- Risks
- Validation and Rollout
- Open Questions

Separate committed scope from possible follow-on work.

## Reference

- Purpose
- Prerequisites
- Commands or Procedure
- Expected Result
- Troubleshooting
- Related References
